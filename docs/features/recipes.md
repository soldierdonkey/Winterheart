# recipes

Winterheart's recipe overrides and custom item chains: string- and leather-bound armor and tools, hammer-made metal parts, the saltpeter-to-gunpowder chain, an early brewing stand, campfire charcoal and moss-to-sponge. Also a few item tags those recipes rely on.

## Files

- `python/recipes/gen_recipes.py`: generates every recipe and item tag below. The tables at the top of the script are the source of truth.
- `config/paxi/datapacks/winterheart_recipes/pack.mcmeta`: the Paxi pack (hand-written).
- `config/paxi/datapacks/winterheart_recipes/data/`: generated output (files with the `gen_recipes.py` `__comment__` marker). TACZ gunsmith recipes in the same pack belong to [tacz-guns](tacz-guns.md).
- Items, textures, names, the brewing changes, the leaching recipe type and the bottle pop-out are in the core mod: see [winterheart-core](winterheart-core.md).

## How it works

Edit `python/recipes/gen_recipes.py`, run it from the instance root, then `/reload`:

```sh
python3 python/recipes/gen_recipes.py
```

The script deletes every file in the pack that carries its own `__comment__` marker, then writes them all again. Files with another marker (from `python/tacz/gen_gunsmith_recipes.py`) or none are left alone.

What it writes:

| What | Recipe IDs | Notes |
| --- | --- | --- |
| Armor (leather, iron, golden, diamond) | `minecraft:<tier>_{helmet,chestplate,leggings,boots}` | Overrides vanilla in place. Lining: `#notreepunching:string` for leather, `minecraft:leather` for the rest. |
| Tools (wooden, stone, iron, golden, diamond) | `minecraft:<tier>_{sword,pickaxe,axe,shovel,hoe}` | Overrides vanilla in place. Binding: string for wooden/stone, leather for the rest. |
| Chainmail armor | `winterheart:equipment/chainmail_<piece>` | Iron nuggets, chains, string. Vanilla has no chainmail recipe. |
| Metal parts (iron, gold, copper, diamond) | `winterheart:crafting/<metal>_{plate_from_hammer,rods_from_plate,ring_from_rod,bolts_from_rod,screw_from_bolt,gear_from_plates_and_ring}` | `notreepunching:tool_damaging_shaped` / `_shapeless`: the `#forge:hammer` is damaged, not used up. |
| Brewing stand | `minecraft:brewing_stand` | Iron rod, gold rings, copper, cobblestone instead of a blaze rod. |
| Gunpowder | `winterheart:gunpowder_from_saltpeter` | 6 `winterheart:saltpeter` + `butchery:sulfur` + 2 `#minecraft:coals` → 16. |
| Leaching | `winterheart:crude_nitrate_from_rich_soil` | Rich soil + 4 purified water bottles → 4 `winterheart:crude_nitrate_bottle`; the soil leaves dirt (`winterheart:shapeless_with_remainders`). |
| Saltpeter | `winterheart:saltpeter_from_smelting` | Smelting `winterheart:potassium_nitrate_bottle`. |
| Charcoal | `winterheart:charcoal_from_campfire_cooking` | Any log on a campfire, 600 ticks. |
| Sponge | `winterheart:sponge_from_smelting_moss_clump` | Smelting `immersive_weathering:moss_clump`. |
| Disabled | `gore_edition:exarrack_can_craft_stone_{axe,axe_two,hoe,hoe_two,pickaxe,shovel}`, `tacz:gunpowder`, `immersive_weathering:green_dye_from_moss_clump` | Same-ID file with `"conditions": [{"type": "forge:false"}]`. |

Item tags (all `"replace": false`):

| Tag | Adds |
| --- | --- |
| `forge:hammer` | `#forge:hammers`, `#forge:tools/hammers`, `#c:tools/hammers`, `#c:hammers`, `#c:hammer` (each optional) |
| `minecraft:brewing_stand_fuel` | `minecraft:coal`, `minecraft:charcoal` |
| `notreepunching:weak_saws` | `minecraft:wooden_axe`, `minecraft:stone_axe` |
| `minecraft:animal_fat` | `butchery:animal_fat` |

The saltpeter chain overall: rich soil + 4 purified water → 4 crude nitrate bottles (crafting, leaves dirt) → potassium nitrate bottle (brewing stand with charred planks) → saltpeter (smelting; the bottle pops out of the furnace) → gunpowder (crafting). Details in [winterheart-core](winterheart-core.md#how-it-works).

## Config / tunables

| Key | File | Default | Effect |
| --- | --- | --- | --- |
| `ARMOR_TIERS`, `TOOL_TIERS`, `*_PATTERNS` | `python/recipes/gen_recipes.py` | see file | Equipment materials and shapes |
| `METALS` | `python/recipes/gen_recipes.py` | iron, gold, copper, diamond | Metals that get a metal part chain |
| `DISABLED` | `python/recipes/gen_recipes.py` | see table above | Recipe IDs switched off |
| `ITEM_TAGS` | `python/recipes/gen_recipes.py` | see table above | Item tag additions |

## Changes

- 2026-11-22: Moved from KubeJS (`kubejs/server_scripts/recipes/{equipment,gunpowder,metal_parts,potions,recipe_fixes,sponge}.js` and the smelting half of `saltpeter.js`) into the Paxi pack `winterheart_recipes`, generated by `python/recipes/gen_recipes.py`. Step 1 of [general-kubejs-removal](../todo/general-kubejs-removal.md). Same recipes as before. The differences: vanilla armor/tool recipes and `minecraft:brewing_stand` are now overridden in place (they were removed and re-added under `kubejs:` IDs), and the other new recipes have `winterheart:` IDs. The removal targets were found by scanning `mods/*.jar` and the vanilla jar for recipes with matching outputs. `potions.js` also removed `minecraft:blaze_rod` from `#minecraft:brewing_stand_fuel`. That was always a no-op (the tag comes from `betterbrewingfuels` and only holds `minecraft:blaze_powder`), so it was dropped. Tested: headless smoke test on `Smoke Test` passed (joined in 53 s, no recipe or tag errors, KubeJS 17/17 server scripts, 0 errors). A temporary probe script confirmed every new recipe ID loads, the disabled IDs are gone, and the item tags contain their new entries (`blaze_powder` still fuels). Not tested by hand in a crafting grid.

- 2026-11-22: Step 2 of the KubeJS removal: the items moved to the core mod and `kubejs:{saltpeter,crude_nitrate_bottle,potassium_nitrate_bottle}` became `winterheart:*`. The leaching recipe is now JSON in this pack (`winterheart:crude_nitrate_from_rich_soil`), so no recipe scripts are left in KubeJS. Tested with [winterheart-core](winterheart-core.md#changes).

## Gotchas

- Generated JSON is overwritten on the next run. Edit the script, not the files.
- Removal is by recipe ID, not by output as in KubeJS. A newly added mod with its own recipe for one of these items won't be removed automatically. Rescan when adding mods.
