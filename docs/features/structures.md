# structures

Hand-built structures placed once per world at fixed spots with a fixed rotation (watchtower, iceberg shipwreck, summit beacon). Worldgen structures always get a random rotation in 1.20.1, so these are pasted with `/place template` by a server script. The templates are exported from WorldEdit saves by Python scripts. Also includes the spawn starter structure.

## Files

- `mod-src/winterheart_structures/` (Java): `FixedStructures.java` places each template once per world, grounds it and applies fixups; `StructureConfig.java` reads the two JSON files below; `WinterheartStructures.java`.
- `datapacks/winterheart_structures/data/winterheart/fixed_structures/placements.json`: template, X/Z and rotation of each placement, written by the [world-painter](../feature-map.md#world) (Struct tab, Save all). Re-read on `/reload`.
- `datapacks/winterheart_structures/data/winterheart/fixed_structures/profiles.json`: how each template sits in the world (anchor, ground layers, foundation, clearing, centre point) and the legacy placed flags.
- `mods/winterheart_structures-1.0.0.jar`: the built jar.
- `datapacks/winterheart_structures/data/winterheart/structures/{watchtower,shipwreck,beacon}.nbt`: structure templates.
- `datapacks/winterheart_structures/data/winterheart/structures/watchtower.fixups.json`: block states that `/place template` recomputes wrongly (Macaw's bridge corners), restored after placing.
- `datapacks/winterheart_structures/`: datapack with the templates above and `/function` versions (`data/winterheart/functions/structures/{beacon,iceberg_shipwreck}.mcfunction`), generated by the `gen_*.py` scripts.
- `python/structures/export_structures.sh`: re-exports every template from its WorldEdit save.
- `python/structures/nbt_to_structure.py`: WorldEdit `.nbt`/`.schem` → structure template, with options to keep world blocks below a layer and merge block-entity NBT.
- `python/structures/schem_to_structure.py`: older `.schem` converter (`--iceberg`, `--drop`, `--keep-inner-air`). Used for the beacon template.
- `python/structures/structure_fixups.py`: writes `<template>.fixups.json`.
- `python/structures/remap_item_ids.py`: rewrites item IDs inside template/schematic NBT and `.snbt` files in place (used when an item changes ID).
- `python/structures/gen_beacon.py`, `python/structures/gen_wreck.py`: procedural generators for the two `.mcfunction` files.
- `config/worldedit/schematics/{watchtower.nbt,shipwreck.schem,shipwreck_chest.snbt}`: WorldEdit sources (the only tracked schematics; see `.gitignore`).
- `config/starterstructure.json5`, `config/starterstructure/schematics/Spawn_v2.3.schem`: the spawn structure placed by the Starter Structure mod.

## How it works

1. **Export.** Build the structure in game, save it with WorldEdit to `config/worldedit/schematics/`, then run `sh python/structures/export_structures.sh` from the instance root. It writes the `.nbt` templates (gzip with mtime 0, so re-exports are byte-identical) and the watchtower fixups.
2. **Place.** At server start, `FixedStructures` force-loads each spot not yet placed in this world; every second it places the ones whose chunks are loaded with `/place template <id> <x> <y> <z> <rotation>`. Placement is tracked in the world state (`fixed_structure_placed:<template>@<x>,<z>`, the key the KubeJS version used), plus `legacy_placed` in `profiles.json` for worlds made before the World Painter. The Y comes from `FIXED_STRUCTURE_PROFILES`:
   - `anchor: 'surface'`: the median heightmap of the footprint's centre and corners. Template layer `groundLayers` goes at the surface. The box above is cleared and a foundation is filled below (`'fill'` slab, or `'columns'` down to ground).
   - `anchor: 'sea'`: template layer `waterline` goes at sea level − 1. Nothing is cleared, and ice in the keel extends to a nearby sea floor.
3. **Fixups.** The mod then reads `<ns>:structures/<name>.fixups.json` from the datapack and writes those block states back (flags 2|16, so neighbours are not recomputed). Only rotation `none` is supported.

The `.mcfunction` versions are for testing by hand (`/function winterheart:structures/beacon`). They have no undo, so run them in a copy of a world.

## Config / tunables

| Key | File | Default | Effect |
| --- | --- | --- | --- |
| `templates`, `default` | `.../fixed_structures/profiles.json` | per template | Anchor, ground layers, foundation, clearing, centre point |
| `structures[]` | `.../fixed_structures/placements.json` | watchtower (0, 400), shipwreck (950, 0), beacon (−1100, 0) | Where each template goes |

## Gotchas

- `iceberg_shipwreck.mcfunction` doesn't match `gen_wreck.py` (10 differing lines around line 2209, already true at commit fa1690b). Either the file was edited by hand or the generator changed after it was run. Regenerating it would change the wreck, so diff it before you overwrite it.
- Fixups only work with rotation `none`.
- The committed `watchtower.nbt` is origin's copy (commit a79295e), not an export of the local `config/worldedit/schematics/watchtower.nbt`. Running `export_structures.sh` rewrites it with different bytes, so check the result in game before you commit it.
- `export_structures.sh` currently stops at the shipwreck: `--merge-nbt: no block entity at template position (18, 29, 25)`. The chest position in `shipwreck_chest.snbt` no longer matches `shipwreck.schem`. The pre-move scripts fail the same way. Fix the position before re-exporting the shipwreck.
- Templates are placed once per world. Moving one in `fixed_structures.json` doesn't move it in an existing world.
